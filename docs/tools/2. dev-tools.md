
# ابزارهای پایه توسعه

در فرایند توسعه وب، علاوه بر آشنایی با HTML، CSS و JavaScript، باید با ابزارهایی که برای نوشتن، اجرا، آزمایش و مدیریت کد استفاده می‌شوند نیز آشنا باشیم.

در این بخش با سه دسته از ابزارهای مهم آشنا می‌شویم:
- ویرایشگر کد( Visual Studio Code) و محیط توسعه
- ترمینال و دستورات پرکاربرد
- مدیریت نسخه با Git و همکاری تیمی با GitLab
- ابزارهای توسعه مرورگر (Browser DevTools)

---

## 1. ویرایشگر کد Visual Studio Code

وی اس کد(**Visual Studio Code (VS Code)**) یک ویرایشگر کد رایگان و چندسکویی است که توسط Microsoft توسعه داده شده است. این ابزار برای نوشتن و ویرایش کد، مدیریت فایل‌های پروژه، اجرای دستورات، اشکال‌زدایی و کار با Git استفاده می‌شود.

از زبان‌ها و فناوری‌های مختلف پشتیبانی می‌کند و با نصب افزونه‌ها(Extensions) می‌توان امکانات آن را گسترش داد.

### بخش‌های اصلی محیط VS Code

محیط VS Code از قسمت‌های مختلفی تشکیل شده است:

- **Explorer:** نمایش فایل‌ها و پوشه‌های پروژه و امکان ایجاد، حذف و جابه‌جایی آن‌ها.
- **Editor:** محیط اصلی برای مشاهده و ویرایش فایل‌های کد.
- **Activity Bar:** نوار کناری برای جابه‌جایی بین بخش‌هایی مانند Explorer، Search، Source Control و Extensions.
- **Terminal:** ترمینال داخلی برای اجرای دستورات بدون نیاز به باز کردن پنجره‌ای جداگانه.
- **Source Control:** نمایش تغییرات فایل‌ها و انجام عملیات Git مانند Stage و Commit.
- **Extensions:** بخشی برای جست‌وجو، نصب و مدیریت افزونه‌ها.
- **Status Bar:** نمایش اطلاعاتی مانند زبان فایل، شماره خط و ستون، وضعیت Git و برخی تنظیمات محیط.

### ترمینال داخلی VS Code

یکی از امکانات کاربردی VS Code، ترمینال داخلی آن است. با استفاده از این قابلیت می‌توان دستوراتی مانند اجرای پروژه، نصب وابستگی‌ها و دستورات Git را مستقیماً در محیط ویرایشگر اجرا کرد.

برای باز کردن ترمینال می‌توان از مسیر زیر استفاده کرد:

`Terminal > New Terminal`

یا از میانبر زیر استفاده کرد:

`Ctrl + `` ` , `Ctrl + j`
ترمینال VS Code می‌تواند از Shellهای مختلفی مانند PowerShell، Command Prompt، Bash و Zsh استفاده کند؛ انتخاب آن به سیستم‌عامل و تنظیمات کاربر بستگی دارد.

### افزونه‌ها (Extensions)

افزونه‌ها قابلیت‌هایی هستند که امکانات جدیدی به VS Code اضافه می‌کنند یا فرایند توسعه را ساده‌تر می‌سازند.

چند نمونه از افزونه‌های پرکاربرد:

| افزونه            | کاربرد                                                                            |
| ----------------- | --------------------------------------------------------------------------------- |
| Prettier          | قالب‌بندی خودکار کد و یکسان‌سازی سبک نوشتار                                       |
| ESLint            | شناسایی مشکلات و رعایت قواعد کدنویسی JavaScript و TypeScript                      |
| Live Server       | اجرای صفحات استاتیک و مشاهده تغییرات در مرورگر                                    |
| GitLens           | نمایش اطلاعات تکمیلی درباره تاریخچه و تغییرات Git                                 |
| Path Intellisense | پیشنهاد مسیر فایل‌ها هنگام نوشتن آدرس آن‌ها                                       |
| Error lens        | برای highlight بهتر خطا ها و پیام ها                                              |
| Auto rename tag   | در صورت عوض کردن تگ، به صورت همزمان closing tag هم نامش عوض شود                   |
| Auto complete tag | نشان دادن لیست برای نوشتن تگ قبل از کامل شدن آن                                   |
| Auto close tag    | بعد از گذاشتن علامت `<` در تگ نوشته شده، به صورت اتومات closing tag نیز ساخته شود |

نکته: نصب تعداد زیادی افزونه لزوماً باعث بهتر شدن محیط توسعه نمی‌شود. بهتر است فقط افزونه‌هایی نصب شوند که واقعاً در پروژه مورد استفاده قرار می‌گیرند.

## 2. ترمینال و دستورات پایه

ترمینال یک محیط متنی برای ارتباط با سیستم‌عامل و اجرای دستورات است. به جای انجام عملیات مختلف از طریق رابط گرافیکی، می‌توان با نوشتن دستور، کارهایی مانند پیمایش پوشه‌ها، ساخت فایل، نصب ابزارها و اجرای برنامه‌ها را انجام داد.

ترمینال در توسعه وب کاربردهای زیادی دارد؛ از جمله:

- اجرای پروژه و سرور توسعه
- نصب و مدیریت پکیج‌ها
- کار با Git
- اجرای ابزارهای توسعه و تست
- مدیریت فایل‌ها و پوشه‌ها

### دستورات پرکاربرد

در جدول زیر چند دستور پایه معرفی شده‌اند:

| دستور | کاربرد |
|---|---|
| `pwd` | نمایش مسیر پوشه فعلی |
| `ls` | نمایش فایل‌ها و پوشه‌های مسیر فعلی |
| `cd folder-name` | ورود به یک پوشه |
| `cd ..` | بازگشت به پوشه بالاتر |
| `mkdir folder-name` | ایجاد یک پوشه جدید |
| `clear` | پاک کردن محتوای قابل مشاهده ترمینال |
| `node --version` | نمایش نسخه Node.js |
| `npm --version` | نمایش نسخه npm |
| `git --version` | نمایش نسخه Git |

بعضی از دستورات ممکن است بسته به Shell یا سیستم‌عامل تفاوت داشته باشند. برای مثال، در PowerShell ویندوز می‌توان از `cls` نیز برای پاک کردن صفحه ترمینال استفاده کرد.

### چند دستور مرتبط با پروژه‌های JavaScript

در پروژه‌هایی که از Node.js و npm استفاده می‌کنند، دستورات زیر کاربرد زیادی دارند:

```bash
# نصب وابستگی‌های تعریف‌شده در package.json
npm install

# نصب یک پکیج به عنوان وابستگی توسعه
npm install -D package-name

# اجرای یکی از اسکریپت‌های تعریف‌شده در package.json
npm run script-name

# مشاهده نسخه Node.js
node --version
```

برای مثال، در پروژه VitePress همین مستندات، دستور زیر سرور توسعه را اجرا می‌کند:

```bash
npm run docs:dev
```

نکته: دستورهای npm فقط مخصوص پروژه‌هایی هستند که از Node.js و npm استفاده می‌کنند؛ اما دستورهای عمومی ترمینال برای کارهای متنوع‌تری کاربرد دارند.

## 3. Git و GitLab

یکی از نیازهای مهم در توسعه نرم‌افزار، مدیریت تغییرات کد است. در طول توسعه ممکن است بارها کدها را تغییر دهیم، قابلیت جدیدی اضافه کنیم یا بخشی از برنامه را اصلاح کنیم.

برای مدیریت این تغییرات، ابزارهایی مانند Git و پلتفرم‌هایی مانند GitLab استفاده می‌شوند.

### Git چیست؟

**Git** یک سیستم کنترل نسخه (Version Control System) توزیع‌شده است که تغییرات فایل‌های پروژه را ثبت و مدیریت می‌کند.

با استفاده از Git می‌توان:

- تاریخچه تغییرات پروژه را مشاهده کرد.
- به نسخه‌های قبلی بازگشت.
- روی قابلیت‌های مختلف به صورت جداگانه کار کرد.
- تغییرات چند توسعه‌دهنده را با یکدیگر ترکیب کرد.
- متوجه شد چه تغییراتی، در چه زمانی و توسط چه کسی ثبت شده‌اند.

Git روی سیستم شخصی نیز قابل استفاده است و برای کار کردن با آن الزاماً نیازی به اینترنت یا GitLab نداریم.

### GitLab چیست؟

**GitLab** یک پلتفرم مبتنی بر Git است که امکاناتی فراتر از کنترل نسخه در اختیار توسعه‌دهندگان و تیم‌ها قرار می‌دهد.

GitLab برای میزبانی مخازن Git و مدیریت همکاری در پروژه‌های نرم‌افزاری استفاده می‌شود.

برخی از قابلیت‌های آن عبارت‌اند از:

- میزبانی Repositoryها
- مدیریت Issueها و تقسیم وظایف پروژه برای اعضا تیم
- ایجاد و بررسی Merge Requestها برای دو branch
- مدیریت کاربران و سطح دسترسی‌ها
- اجرای فرایندهای CI/CD
- مشاهده تاریخچه و فعالیت‌های پروژه

### تفاوت Git و GitLab

| Git | GitLab |
|---|---|
| یک سیستم کنترل نسخه است. | یک پلتفرم مدیریت پروژه و مخازن Git است. |
| تغییرات را ثبت و مدیریت می‌کند. | امکان میزبانی و همکاری روی مخازن را فراهم می‌کند. |
| روی سیستم محلی قابل استفاده است. | معمولاً از طریق وب و سرور در دسترس است. |
| ابزارهایی مانند Commit، Branch و Merge را فراهم می‌کند. | امکاناتی مانند Issue، Merge Request و CI/CD را ارائه می‌دهد. |

بنابراین Git و GitLab جایگزین یکدیگر نیستند؛ بلکه در کنار هم استفاده می‌شوند.

## 4. مفاهیم پایه در Git و GitLab

برای کار با Git و GitLab باید با چند مفهوم اصلی آشنا باشیم.

### Repository

**Repository (مخزن)** محلی برای نگهداری فایل‌های پروژه و تاریخچه تغییرات آن است.

یک Repository در واقع شامل فایل‌های پروژه و اطلاعاتی است که Git برای ثبت و مدیریت نسخه‌ها استفاده می‌کند.

هر پروژه می‌تواند یک Repository مستقل داشته باشد.
برای تعریف یک Repository در یک پروژه، در پوشه فعلی آن میتوانید از دستور زیر استفاده کنید:
```bash
git init
```

البته بهتر است قبل از آن، مطمعن شوید در آن پوشه یک repository دیگر فعال نیست:
```bash
git status
```

### Staging
فایل‌های جدید ساخته شده، باید به حالت tracking در بیان تا بتوانیم تغییرات را دنبال و ثبت کنیم
```bash
git add filename
```
به عبارتی دیگر، فایل مورد نظر ما الان در حالت staging قرار دارد. مثل یک اتاق انتظار برای تغییرات فایل‌های ما می‌باشد.
- `git add filename` - یک فایل را stage میکند
- `git add --all` or `git add -A` - همه فایل‌ها stage می‌شوند
- `git status` - مشاهده فایل‌تغییر کرده
- `git restore --staged filename` - فایل را از حالت staging خارج می‌کند. 
### Commit
**Commit** یک ثبت از وضعیت تغییرات انتخاب‌شده پروژه است.
هر Commit معمولاً شامل یک پیام توضیحی است که مشخص می‌کند چه تغییری انجام شده است.


```bash
git add .
git commit -m "feat: add homepage"
```

در این مثال ابتدا تغییرات برای ثبت انتخاب شده‌اند و سپس با پیام `feat: add homepage` در تاریخچه Git ذخیره شده‌اند.

بهتر است Commitها کوچک، معنادار و مرتبط با یک کار مشخص باشند.

### Branch
**شاخه(Branch)** امکان ایجاد یک مسیر مستقل برای توسعه را فراهم می‌کند.

برای مثال، می‌توان برای اضافه کردن یک قابلیت جدید، شاخه‌ای جدا از شاخه اصلی ایجاد کرد و تغییرات را بدون دست‌کاری مستقیم نسخه اصلی انجام داد.

نمونه‌ای از شاخه‌های رایج:

- `main`: شاخه اصلی پروژه
- `dev`: شاخه توسعه و ادغام تغییرات
- `feature/login`: شاخه مربوط به توسعه قابلیت ورود

ایجاد و جابه‌جایی بین شاخه‌ها:

```bash
# مشاهده شاخه‌های موجود
git branch

# ایجاد یک شاخه جدید و ورود به آن
git switch -c feature/login

# جابه‌جایی به یک شاخه موجود
git switch main
```
یا:
```bash
git checkout -b feature/login

git checkout main
```

### Push
**Push** به معنای ارسال Commitهای محلی به یک مخزن راه دور (Remote Repository) است.

به کمک Push می‌توان تغییراتی را که روی سیستم شخصی ثبت کرده‌ایم، به مخزن میزبانی‌شده در GitLab ارسال کرد.
```bash
git push origin feature/login
```

در این مثال، شاخه `feature/login` به مخزن راه دوری با نام `origin` ارسال می‌شود.

نکته: Push به معنای Merge کردن تغییرات در شاخه اصلی نیست؛ فقط Commitها را به مخزن راه دور ارسال می‌کند.

### Merge Request

**Merge Request (MR)** قابلیتی در GitLab است که با استفاده از آن می‌توان درخواست ادغام تغییرات یک شاخه در شاخه دیگر را ثبت کرد.

برای مثال، فرض کنید قابلیتی را در شاخه `feature/login` توسعه داده‌ایم. پس از Push کردن تغییرات، می‌توان یک Merge Request از این شاخه به `dev` ایجاد کرد.

در این فرایند، تغییرات قابل بررسی هستند و می‌توان پیش از ادغام، درباره آن‌ها نظر داد یا درخواست اصلاح کرد.

Merge Request معمولاً شامل موارد زیر است:
- شاخه مبدأ (Source Branch)
- شاخه مقصد (Target Branch)
- توضیح تغییرات انجام‌شده
- ارتباط با Issue مربوطه
- بررسی و بازبینی تغییرات
در GitHub معمولاً مفهوم مشابهی با نام **Pull Request (PR)** شناخته می‌شود.

### Merge Conflict
**Merge Conflict (تعارض ادغام)** زمانی رخ می‌دهد که Git نتواند تغییرات دو شاخه را به صورت خودکار و بدون تصمیم انسانی ترکیب کند.

برای مثال، ممکن است دو توسعه‌دهنده بخش یکسانی از یک فایل را به شکل متفاوتی تغییر داده باشند.

در چنین شرایطی Git از کاربر می‌خواهد مشخص کند نسخه نهایی چگونه باید باشد.

نمونه‌ای از نشانه‌های یک Conflict در فایل:

```text
<<<<<<< HEAD
<h1>Welcome to my website</h1>
=======
<h1>Welcome to our website</h1>
>>>>>>> feature/homepage
```

معنای نشانه‌ها:

- `<<<<<<<`: شروع بخش دارای تعارض
- `=======`: جداکننده دو نسخه متفاوت
- `>>>>>>>`: پایان بخش تعارض

برای حل تعارض باید کد نهایی موردنظر را انتخاب یا ترکیب کنیم و سپس علامت‌های مربوط به Conflict را حذف کنیم.

پس از اصلاح فایل، باید آن را بررسی و آزمایش کرده و تغییرات حل تعارض را دوباره Commit کنیم.

## 5. آشنایی با Browser DevTools

**Developer Tools (DevTools)** مجموعه‌ای از ابزارهای داخلی مرورگر است که برای بررسی، آزمایش و اشکال‌زدایی صفحات وب استفاده می‌شود.

این ابزارها به توسعه‌دهندگان کمک می‌کنند ساختار HTML، استایل‌های CSS، کدهای JavaScript و درخواست‌های شبکه را بررسی کنند.

در مرورگرهایی مانند Google Chrome و Microsoft Edge می‌توان با فشردن کلید `F12` یا `Ctrl + Shift + I` ابزار DevTools را باز کرد.

در ادامه سه بخش پرکاربرد آن را بررسی می‌کنیم.

### Elements

بخش **Elements** برای بررسی ساختار DOM صفحه و مشاهده یا آزمایش تغییرات HTML و CSS استفاده می‌شود.

در این بخش می‌توان:

- ساختار عناصر HTML را مشاهده کرد.
- ویژگی‌ها و محتوای عناصر را بررسی کرد.
- قوانین CSS اعمال‌شده روی عناصر را مشاهده کرد.
- تغییرات موقتی در HTML و CSS ایجاد کرد.
- مشکلات مربوط به ظاهر و چیدمان عناصر را بررسی کرد.

برای مثال، اگر بخواهیم رنگ یک عنوان را آزمایش کنیم، می‌توانیم عنصر مربوط به آن را در Elements انتخاب کرده و مقدار `color` را در بخش Styles تغییر دهیم.

نکته: تغییراتی که از طریق DevTools انجام می‌دهیم، معمولاً موقتی هستند و مستقیماً فایل‌های اصلی پروژه را تغییر نمی‌دهند.

### Console

بخش **Console** برای مشاهده پیام‌ها، هشدارها و خطاهای JavaScript و همچنین اجرای مستقیم کدهای JavaScript استفاده می‌شود.

برای مثال، اگر در کد خود دستور زیر را بنویسیم:

```javascript
console.log("Hello from JavaScript!");
```

پیام آن در Console نمایش داده می‌شود.

از Console می‌توان برای موارد زیر استفاده کرد:

- مشاهده خطاهای JavaScript
- بررسی مقدار متغیرها
- آزمایش سریع دستورات JavaScript
- مشاهده پیام‌های ثبت‌شده با `console.log`
- بررسی هشدارها و خطاهای زمان اجرا

نمونه:

```javascript
const username = "Ali";

console.log(username);
console.error("Something went wrong!");
```

در این مثال مقدار متغیر و یک پیام خطا در Console نمایش داده می‌شود.

### Network

بخش **Network** برای بررسی ارتباطات شبکه‌ای و درخواست‌هایی استفاده می‌شود که مرورگر هنگام بارگذاری یک صفحه ارسال و دریافت می‌کند.

برای مثال، وقتی یک وب‌سایت را باز می‌کنیم، مرورگر ممکن است درخواست‌هایی برای دریافت موارد زیر ارسال کند:

- فایل‌های HTML
- فایل‌های CSS و JavaScript
- تصاویر و فونت‌ها
- اطلاعات دریافتی از APIها

در Network می‌توان اطلاعاتی مانند موارد زیر را مشاهده کرد:

- آدرس درخواست (Request URL)
- متد درخواست مانند GET و POST
- کد وضعیت پاسخ (Status Code)
- زمان دریافت پاسخ (Duration)
- سرآیند(Header)های درخواست و پاسخ
- داده‌های ارسالی و پاسخ دریافتی

برای مثال، اگر یک درخواست API با خطا مواجه شود، می‌توان آن را در Network پیدا کرد و اطلاعات درخواست و پاسخ را بررسی کرد.

### تفاوت کاربرد سه بخش اصلی DevTools

| بخش | کاربرد اصلی |
|---|---|
| Elements | بررسی ساختار DOM و استایل‌های CSS |
| Console | مشاهده خطاها و اجرای کد JavaScript |
| Network | بررسی درخواست‌ها و پاسخ‌های شبکه |

## 7. جمع‌بندی

ابزارهای معرفی‌شده هر کدام نقش متفاوتی در فرایند توسعه وب دارند:

- **VS Code:** محیطی برای نوشتن، ویرایش و مدیریت کد و فایل‌های پروژه.
- **Terminal:** محیطی برای اجرای دستورات و ابزارهای توسعه.
- **Git:** ابزاری برای کنترل نسخه و مدیریت تاریخچه تغییرات.
- **GitLab:** پلتفرمی برای میزبانی مخازن و مدیریت همکاری روی پروژه.
- **Browser DevTools:** مجموعه‌ای از ابزارها برای بررسی و اشکال‌زدایی صفحات وب.

شناخت و استفاده صحیح از این ابزارها باعث می‌شود فرایند توسعه منظم‌تر، قابل پیگیری‌تر و ساده‌تر شود.
