# نسخه‌گذاری معنایی (SemVer)

<div style="background: var(--vp-c-bg-soft); padding: 16px; border-radius: 8px; border-right: 4px solid var(--vp-c-brand-1); margin-bottom: 24px;">
  <strong>SemVer چیست؟</strong><br/>
  نسخه‌گذاری معنایی یک قرارداد استاندارد است تا توسعه‌دهندگان بدانند تغییرات یک نسخه جدید چه تأثیری بر پروژه‌هایشان دارد.
</div>

## ساختار یک نسخه (مثلاً `2.4.1`)

| بخش | عدد | معنی و کاربرد |
| :--- | :--- | :--- |
| **MAJOR** | `2` | تغییرات ناسازگار (Breaking Changes). اگر این عدد تغییر کند، ممکن است کدهای قبلی شما دیگر کار نکنند. |
| **MINOR** | `4` | اضافه شدن قابلیت جدید، اما به صورت سازگار با نسخه‌های قبلی (Backward Compatible). |
| **PATCH** | `1` | رفع باگ‌های امنیتی یا مشکلات کوچک، بدون اضافه کردن قابلیت جدید. |

::: tip نسخه‌های صفر (`0.y.z`)
اگر نسخه پروژه‌ای با `0.` شروع شود (مثل `0.5.2`)، به این معنی است که پروژه هنوز در مرحله توسعه اولیه است و هیچ API پایدار و قطعی‌ای ندارد.
:::

## نسخه‌های پیش‌انتشار (Pre-releases)
گاهی قبل از انتشار یک نسخه پایدار، نسخه‌های آزمایشی منتشر می‌شوند:
- **`1.0.0-alpha`**: نسخه بسیار اولیه و پر از باگ.
- **`1.0.0-beta`**: نسخه‌ای که قابلیت‌ها کامل شده اما هنوز تست نهایی نشده است.
- **`1.0.0-rc.1`**: نسخه کاندید انتشار (Release Candidate) که تقریباً پایدار است.

::: warning تضمین بدون باگ
SemVer فقط به شما می‌گوید تغییرات از نظر ساختاری چه هستند، اما **هرگز تضمین نمی‌کند** که نرم‌افزار بدون باگ است!
:::
