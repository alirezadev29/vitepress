
# نحوه کار وب (How the Web Works)

مبحث **نحوه عملکرد وب** شرح کلی از وقایعی ارائه می‌دهد که هنگام استفاده از یک مرورگر وب برای رفتن به یک صفحه وب رخ می‌دهد.

برای درک بهتر دنیای شبکه و برنامه‌نویسی، دو مفهوم **Internet** و **Web** رو بهتر است بدانیم.

---

## 1. اینترنت (Internet)

اینترنت یک شبکه جهانی و گسترده است از شبکه‌های کامپیوتری، که برای دستگاه‌های مختلف در سراسر جهان امکان برقراری ارتباط، اشتراک‌گذاری اطلاعات و... را فراهم می‌کند.

به زبان ساده، اینترنت زیرساختی است که کامپیوترها، موبایل‌ها، سرورها و سایر دستگاه‌ها را به یکدیگر متصل می‌کند.

### ویژگی‌های اینترنت

1. **جهانی بودن (Global):** دستگاه‌های مختلف در سراسر دنیا می‌توانند به اینترنت متصل شوند.
2. **غیرمتمرکز بودن (Decentralized):** اینترنت توسط یک کامپیوتر یا حتی سازمان واحد کنترل نمی‌شود.
3. **ارتباط بین دستگاه‌ها:** امکان برقراری ارتباط و تبادل اطلاعات بین کامپیوترها و سرورها را فراهم می‌کند.
4. **استفاده از پروتکل‌ها:** برای انتقال اطلاعات از پروتکل‌هایی مانند TCP/IP استفاده می‌کند.
5. **ارائه سرویس‌های مختلف:** سرویس‌هایی مانند وب، ایمیل، انتقال فایل، تماس اینترنتی و بازی‌های آنلاین بر بستر اینترنت فعالیت می‌کنند.

### برخی از کاربردهای اینترنت

- ارسال و دریافت ایمیل
- برقراری تماس‌های صوتی و تصویری
- استفاده از وب‌سایت‌ها
- ارتباط بین دستگاه‌ها و سرورها

---

## 2. وب (Web یا WWW)

وب (World Wide Web) مجموعه‌ای از صفحات و منابع اطلاعاتی به‌هم‌ پیوسته است که از طریق اینترنت قابل دسترسی هستند.

برای مثال، وقتی مرورگر خود را باز می‌کنید و وارد یک وب‌سایت مانند Google یا Wikipedia می‌شوید، در حال استفاده از وب هستید.

تفاوت آن با اینترنت این است که **اینترنت یک زیرساخت جهت ارتباط است، اما وب یکی از سرویس‌هایی است که از آن استفاده می‌کند.**

### نحوه کارکرد وب

فرض کنیم می‌خواهیم وارد یک سایت شویم:

1. مرورگر را باز می‌کنیم و آدرس `google.com` را وارد می‌کنیم.
2. مرورگر ما از طریق اینترنت، سرور موردنظر را پیدا کرده و به آن متصل می‌شود.
3. مرورگر با استفاده از پروتکل HTTP یا HTTPS درخواست ارسال می‌کند.
4. سرور درخواست را دریافت کرده و آن را پردازش می‌کند.
5. پس از پردازش، سرور یک Response برای مرورگر ارسال می‌کند (اطلاعات مورد نیاز).
6. مرورگر پس از دریافت اطلاعات، آن‌ها را پردازش کرده و صفحه وب‌سایت مورد نظر را نمایش می‌دهد.

این ارتباط براساس معماری **Client-Server** انجام می‌شود. (کامپیوترهایی که به اینترنت متصل هستند، Client و Server می‌گوییم.)

---

## 3. ریزجزئیات پشت صحنه (Behind the Scenes)

در مورد کارکرد وب به صورت کلی صحبت کردیم. حالا بهتر است بدانیم پشت صحنه چه اتفاقاتی صورت می‌گیرد:

### 1. وارد کردن URL

کاربر مرورگر را باز کرده و یک URL را در نوار آدرس وارد می‌کند، URL در اینجا همان آدرس Source سایت مورد نظر ما است.

مثلاً:

`https://www.google.com`

### 2. بررسی حافظه Cache

حافظه Cache (حافظه پنهان) مرورگر، یک فضای ذخیره‌سازی موقت است که نسخه‌هایی از منابع از قبل دانلود شده مثل تصاویر، فایل‌های استایل (CSS) و فایل‌های JavaScript را در خود نگه می‌دارد.

مرورگر بررسی می‌کند که آیا منابع مورد نیاز در حافظه پنهانش موجود و معتبر هستند یا خیر.

اگر نسخه‌های معتبری موجود باشد، مرورگر ممکن است به‌جای دانلود مجدد آن‌ها، از همان نسخه‌های موجود استفاده کند.

در غیر این صورت، مرورگر درخواست دریافت آن منابع را به سرور ارسال می‌کند.

### 3. ترجمه نام دامنه با استفاده از DNS

**DNS (Domain Name System)**

مرورگر برای اتصال به وب‌سایت، به آدرس IP سرور نیاز دارد.

مرورگر ابتدا بررسی می‌کند که آیا رکورد DNS در حافظه کش (Cache) موجود است یا خیر. اگر موجود نباشد یا منقضی شده باشد، از DNS برای تبدیل نام دامنه به آدرس IP استفاده می‌کند.

پس از به‌دست آمدن آدرس IP، مرورگر می‌تواند موقعیت سرور را پیدا کرده و برای برقراری اتصال اقدام نماید.

درواقع آدرس‌های واقعی وب، عبارت‌هایی که برای جست‌وجو استفاده می‌کنیم نیستند. بلکه اعداد خاصی هستند؛ مثلاً:

`192.0.2.172`

مثلاً برای google.com که آیپی آن به این صورت است:

`142.251.142.206`

### 4. آدرس‌دهی و برقراری ارتباط

آدرس‌دهی IP، به دستگاه‌های موجود در یک شبکه، آدرس‌های منطقی اختصاص می‌دهد و بدین‌وسیله امکان شناسایی و دسترسی به آن‌ها را فراهم می‌سازد.

هنگامی که یک مرورگر درخواستی ارسال می‌کند، آدرس IP مقصد به مسیریاب‌ها (روترها) کمک می‌کند تا بسته‌های داده را به سمت سرور صحیح هدایت کنند.

بدون آدرس‌دهی IP، دستگاه‌ها فاقد اطلاعات آدرس‌دهیِ لازم برای مسیریابی داده‌ها به سمت مقصد مورد نظر خواهند بود.

در نهایت، مرورگر اتصال خود را با سرور برقرار می‌کند.

### 5. ارسال درخواست HTTP

پس از برقراری ارتباط، مرورگر یک درخواست HTTP ارسال می‌کند تا از سرور، منبع یا یک عمل خاص را درخواست کند.

یک درخواست HTTP می‌تواند شامل اجزای زیر باشد:

- **متد (Method):** نوع عملیات را مشخص می‌کند؛ برای مثال، متد GET برای دریافت یک منبع و متد POST برای ارسال داده‌ها به کار می‌رود.
- **مسیر (Path):** منبعِ مورد درخواست را مشخص می‌کند (مانند `/menu`).
- **سرآیندها (Headers):** اطلاعات تکمیلی درباره درخواست را ارائه می‌دهند.
- **بدنه (Body):** در صورت نیاز، حاوی داده‌هاست. برای نمونه، اطلاعاتی که از طریق یک فرم ارسال می‌شوند.

### 6. پردازش و پاسخ سرور

سرور منابع ایستا (Static Resources) را مستقیماً ارائه می‌دهد و درخواست‌های پویا (Dynamic Requests) را به سرور برنامه (Application Server) ارجاع می‌دهد.

سرور برنامه نیز منطق برنامه را پردازش کرده و در صورت نیاز، داده‌ها را از پایگاه داده بازیابی می‌کند.

سرور یک پاسخ HTTP ارسال می‌کند که شامل موارد زیر است:

- **کد وضعیت (Status Code):** نشان‌دهنده نتیجه است، مانند `200 OK` (موفق) یا `404 Not Found`.
- **سرآیندها (Headers):** شامل اطلاعاتی درباره نوع محتوا و قوانین کش‌کردن (Caching) هستند.
- **محتوای پاسخ:** منبع درخواست‌شده یا داده‌های پاسخ (در صورت وجود).

### 7. رندر کردن صفحه وب در مرورگر

مرورگر سند دریافت‌شده را تجزیه (Parse) می‌کند، چیدمان و موقعیت عناصر صفحه وب را محاسبه می‌نماید و در نهایت صفحه را روی نمایشگر رندر می‌کند تا کاربر بتواند آن را مشاهده کرده و با آن تعامل داشته باشد.

### 8. بارگذاری منابع و تعاملات

مرورگر منابع تکمیلی نظیر فایل‌های CSS، JavaScript، تصاویر و فونت‌ها را که در حافظه کش (Cache) موجود نیستند، بارگذاری می‌کند.

سپس این منابع را پردازش می‌کند تا محتوا، استایل‌ها و قابلیت‌های تعاملی صفحه وب را نمایش دهد.

هنگامی که کاربران روی دکمه‌ها کلیک می‌کنند، فرم‌ها را ارسال می‌کنند یا در صفحات جابه‌جا می‌شوند، ممکن است کدهای جاوااسکریپت درخواست‌هایی را به سرور یا یک API ارسال کنند تا تبادل داده صورت گیرد.

سرور این درخواست‌ها را پردازش کرده و داده‌ها یا محتوای به‌روزرسانی‌شده را بازمی‌گرداند؛ مرورگر نیز بر حسب نیاز، آن‌ها را نمایش می‌دهد.
